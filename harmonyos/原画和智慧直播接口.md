**视频流接口文档**

前端 API 请求统一以 `/api` 为前缀，并携带 `satoken` 请求头。

| 场景 | 接口/协议 | 用途 |
|---|---|---|
| 加载摄像头 | `GET /api/farmSite/camera?farmSiteId={id}` | 获取 `id`、`name`、`pushName`、`url`、`status` 等摄像头配置 |
| 原画直播 | HTTP-FLV | `flv.js` 直接拉取原始摄像头流 |
| 智慧直播初始化 | `POST /api/live/detection-session` | 创建算法检测会话，返回算法视频流与检测元数据 WebSocket 地址 |
| 智慧直播画面 | HTTP-FLV | `flv.js` 拉取算法生成的 `{streamId}_detection.flv` |
| 智慧直播检测框 | WebSocket | 接收识别框坐标并在 Canvas 上覆盖绘制 |


```http
GET /api/farmSite/camera?farmSiteId=1
satoken: {登录令牌}
```

```json
{
  "code": 200,
  "message": "地块摄像头获取成功",
  "data": [
    {
      "id": 73,
      "name": "鸡舍一号摄像头",
      "pushName": "rtmp://example.com/live/camera_73",
      "url": "http://example.com:8080/live/camera_73.flv",
      "status": 1
    }
  ]
}
```

**原画直播**

原画模式不再额外申请播放接口。前端从摄像头的 `pushName` 或 `url` 生成候选 FLV 地址，例如：

```text
rtmp://host/live/camera_73
→ http://host:8080/live/camera_73.flv
```

随后使用 `flv.js` 通过 HTTP-FLV 拉取二进制媒体流，挂载到 `<video>` 的 MSE 缓冲区播放；首帧超时为 15 秒，卡顿 3 秒会触发恢复逻辑。实现见 [useFlvPlayer.ts](C:/Users/lip/Desktop/面经/项目/监控中心/smart-farm/src/composables/useFlvPlayer.ts:82)。

**智慧直播**

前端只向业务后端申请“智慧直播会话”，再按响应中的地址连接算法产出的媒体流。

流程如下：

```text
切换“智绘直播”
  → POST /api/live/detection-session { deviceId }
  → 响应返回 algoFlvUrl、wsUrl、streamId、algoEpoch、ticket
  → flv.js 播放 algoFlvUrl（实际视频画面）
  → WebSocket 连接 wsUrl（接收检测框坐标）
  → Canvas 覆盖绘制检测框
```

```http
POST /api/live/detection-session
satoken: {登录令牌}

{ "deviceId": 73 }
```

返回数据中的两个连接地址由后端动态下发：

```json
{
  "streamId": "camera_73",
  "algoEpoch": 12,
  "algoFlvUrl": "http://{SRS地址}:8080/live/camera_73_detection.flv",
  "wsUrl": "ws://{业务后端地址}/ws/live/detection",
  "ticket": "短期票据",
  "frameMetadataEnabled": true
}
```

- `algoFlvUrl`：真正承载算法处理后视频画面的 HTTP-FLV 地址。前端通过 `flv.js.createPlayer({ type: "flv", isLive: true })` 拉流播放。
- `wsUrl`：不是视频流，只传识别结果。前端拼接 `stream_id`、`detection_epoch`、`ticket` 后建立 WebSocket。
- 收到 `frame_meta` 后，前端依据视频尺寸缩放检测框坐标并绘制到 `<canvas>`，视频本身仍来自 `algoFlvUrl`。
